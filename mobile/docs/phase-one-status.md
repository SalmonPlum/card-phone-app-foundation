# First development phase

This document records the historical foundation checkpoint. A native draw preview was added afterward; see [current motion validation](android-validation.md).

This phase implements Tasks 1–3 of the approved plan: the Expo application shell, bilingual deck packages and secure-random primitives, and the packet-aware session engine. It does not yet implement the native shuffle scene, catalogue grid, results, or complete navigation. Launching the current app shows the foundation shell.

## Implemented

- React Native/Expo TypeScript shell and Android/iOS-compatible module choices.
- Czech/English dictionaries and complete bilingual sample content.
- Eight-card sample and distinct three-card alternate deck; static local artwork and validation.
- Stable numeric IDs, including zero, with no dependence on array positions.
- Expo Crypto adapter, unbiased integer rejection sampling, and Fisher–Yates shuffle.
- Pure packet-aware session transitions, no repeated cards, current-packet draw boundary, lower-stack top selection, stale-callback guards, and explicit confirmation.
- Genuine npm lockfile generated by the user's successful installation.

## Try the current shell on the phone

```bash

env ANDROID_HOME="$HOME/Android/Sdk" JAVA_HOME="/usr/local/android-studio/jbr" PATH="$PATH:$HOME/Android/Sdk/platform-tools" npm run android -- --device
```

Connect the phone by USB, enable USB debugging, and approve this computer on the phone. The initial native build may download Android/Gradle components. This command is a host-side instruction, not a claim it has been run successfully in this session. This environment blocks ADB's listener, so device launch could not be verified here.

For subsequent JavaScript edits after the development build is installed, use `npm start`. Press `j` in Expo's terminal to open React Native DevTools.
